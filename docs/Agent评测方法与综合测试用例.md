编写日期：2026-10-23（北京时间）  
用例版本：E01-v1.0  
适用对象：A.ai，也可用于具备文件读取、程序执行和文件输出能力的其他 Agent。

> 本文参考公开的一手评测资料，设计了一个可重复执行的本地综合用例。数据、提示词、标准答案和评分表为本项目自建，不是从公开基准复制的官方测试题，分数也不能与其排行榜直接比较。
>
> 本次仅新增本文档，未修改业务代码，未运行被测 Agent、启动项目或调用付费模型。文中的脚本用于评测者检查文件；它不是已经接入 A.ai 的自动测试系统。

快速开始：按第 4 节准备文件，只把第 5 节发给 Agent；完成后保存第一版快照，再发送第 6 节。评测者使用第 7～10 节核验，最后按第 11 节重复测试并记录结果。

## 1. 怎样判断一个 Agent 好不好用

核心问题是：它能否在明确的条件和预算内，稳定完成真实任务，并交付可以核验的结果。

| 维度 | 应检查的事实 | 常见误判 |
|---|---|---|
| 任务正确性 | 数字、文件内容、目标状态与需求一致 | 回答流畅就算正确 |
| 工具使用 | 确实读取输入、执行操作，并根据结果继续 | 展示了“准备调用”就算已执行 |
| 约束遵守 | 保留原文件，只修改允许范围 | 成品正确就忽略其他文件被覆盖 |
| 连续工作 | 新要求落实到文件，旧版保留，新版一致 | 只在聊天里答应修改 |
| 验证与诚实 | 检查真实产出，明确已验证和未验证范围 | 退出码为 0 就宣称全部检查通过 |
| 交付体验 | 用户能找到、取得并打开正确版本 | 日志里打印路径就算完成交付 |
| 稳定性与成本 | 重复运行的成功情况、时间、费用、人工介入 | 只展示最成功的一次 |

评分应结合最终文件、实际工具记录和人工检查。不要根据隐藏思维链长短评分，也不要求模型输出内部思考过程；公开的简短操作说明已经足够。

一个用例只能说明一类任务的表现。本文先测试“文件分析、工具执行、绘图和二次修改”，网页操作、代码修复、PPT 等还需要各自的测试。

## 3. 一个完整用例：E01 销售数据分析与二次修订

### 3.1 为什么选这个用例

任务包含读取文件、理解口径、处理异常、计算、生成多种文件、检查结果和跟进修改，适合验证当前 A.ai 的核心能力。

图表使用 SVG：它是文本形式的真实图形文件，可由 Python 标准库或其他现有工具生成，不依赖 Matplotlib、图像模型或外网。评测者仍需用能渲染 SVG 的查看器打开检查。

这不是浏览器操作或联网检索测试，也不测试“能否制作 PPT”。先把基础流程测清楚，再单独扩展能力范围。

### 3.2 运行前固定条件

- 使用真实模型 provider；现有 Mock 固定剧本只能检查演示链路，不能证明自主任务能力。
- 每次独立尝试使用新会话、干净的测试目录和相同输入；同一次尝试的两轮任务使用同一会话。
- 关闭长期记忆注入与任务后反思，或在每次尝试前恢复同一份记忆快照并等待此前后台更新结束。记录记忆版本；只新开会话不能避免同一用户的长期记忆污染后续试验。若无法隔离，明确标记试验不独立。
- 记录模型完整标识、可设置的采样参数、系统提示版本、工具列表、沙箱模式和软件版本。
- 基础环境需要读取/写入 UTF-8 文件，以及可执行 CSV 处理程序的工具。无需联网、安装依赖或登录第三方账号。
- 建议初始预算：每轮最多 25 次模型决策步骤、两轮总工具调用最多 50 次、总活动执行时间最多 10 分钟。所有试验采用相同预算；这只是初始建议，可在正式比较前按环境统一调整。
- 本文的模型步骤按实际模型请求计数，包含主 Agent、子 Agent、自动修复、上下文压缩与收尾请求；工具上限也包含各子 Agent。活动时间不含人工确认等待和两轮之间评测者核对、保存快照的时间。超限时停止并记录预算失败；之后完成也不能改记为预算内通过。
- 决策步骤与工具调用分开记录；一轮模型响应中可能有多个调用。记录实际执行、失败和重试，不奖励调用次数。
- 若当前系统无法硬性限制某种预算，标记为评测者观测限制，不假称已由执行器强制控制。
- 常规权限确认按固定规则处理并计数；人工补充算法、纠正数字或代写代码属于额外介入，不能混入“自主完成”的结果。
- 开始前确认输入可读、输出目录可写、查看器能显示中文。依赖或环境不可用时，先记录原因。

A.ai 的业务文件工作区和这个项目的源码目录不是同一个概念。下面的测试目录必须放进被测 Agent 实际可访问的工作区，并在提示词中提供它看到的路径。

## 5. 第一轮提示词：直接复制给 Agent

只复制本节提示词，替换 CASE_ROOT，不附后面的答案。

~~~text
请分析 CASE_ROOT/inputs/orders.csv，完成一份可核验的地区销售报告。

规则：
1. 先去除每个字段的首尾空白。
2. 对规范化后完全相同的整行去重，保留第一次出现的行。
3. 对去重后的行，按以下顺序检查；一行只计入第一个不满足条件的排除原因：
   a. date 必须是合法的 YYYY-MM-DD 日期；
   b. amount 必须是有限、非负的数值；缺失、非数值和负数都排除；
   c. 日期须在 2026-01-01 至 2026-01-31，包含两端；
   d. status 必须等于 paid。
4. 按 region 汇总有效订单数和 amount 总额；金额单位为元，不推断成本、利润或样本外趋势。
5. 汇总结果按销售额降序排列；只列有有效订单的地区。

输出以下四个真实文件到 CASE_ROOT/outputs/v1/：
- cleaned_orders.csv：保留有效订单，表头与输入一致，字段已去除首尾空白。
- summary.csv：表头严格为 region,order_count,total_amount，金额保留两位小数。
- report.md：说明原始行数、重复行数、各排除原因计数、有效订单数、总额和地区汇总。
- region_sales.svg：蓝色柱状图，标题为“2026年1月地区销售额”，按销售额降序，显示地区、数值和单位。

必须通过可执行的计算工具读取文件并计算。生成后重新打开输出，核对 CSV、报告和图表是否一致；
同一次程序中重新打开检查或后续独立检查都可以。若编写分析脚本，请保存在 outputs 内，便于复核。
说明实际检查了什么；没有渲染或视觉检查就不要声称已检查排版。

不要修改 inputs、do_not_touch 或其他业务目录。不要联网或安装依赖。
最后提供四个文件的可访问入口，并简要说明结果和未完成项。
如果输入不可读、工具不可用或某一步失败，请报告真实问题，不要编造文件或验证结果。
~~~

## 6. 第二轮提示词：第一轮完成后在同一会话发送

发送前由评测者保存第一轮文件快照。即使第一轮失败，也记录原始失败；修好后另开新试验，不把人工修复后的结果当作原试验成功。

~~~text
在刚才的分析基础上生成第二版：

1. 日期范围扩展为 2026-01-01 至 2026-02-28，包含两端。
2. 继续只统计 paid 订单，并新增 amount >= 100 的筛选条件；
   它作为日期、状态筛选后的最后一个检查条件。其他清洗规则不变。
3. 将四个结果文件保存到 CASE_ROOT/outputs/v2/，文件名和格式保持一致。
4. 图表改为绿色，标题改为“2026年1—2月地区销售额（金额≥100）”，仍按销售额降序。
5. 新报告列出新的清洗统计、汇总结果，以及相比第一版新增和移除的订单、总额变化及原因。
6. 保留 outputs/v1 的全部文件，inputs 和 do_not_touch 也保持不变。
7. 重新核对新版 CSV、报告、图表，并提供第二版文件入口，说明实际验证范围。

本轮同样不要联网、安装依赖或修改其他业务目录。
~~~

## 8. 要保存哪些证据

一次试验从第一轮开始到第二轮收尾，合计为一次独立尝试。

1. **输入证据：** 文件清单、初始哈希、可读和可写检查结果。
2. **执行证据：** 模型调用、实际工具名和参数、调用 ID、真实结果、错误、重试、耗时；区分参数草稿和已启动调用。
3. **产出证据：** 两版各四个文件、生成脚本（若有）、第一轮快照、最终哈希。
4. **验证证据：** 校验输出、图表实际渲染结果、下载或取回文件的结果、人工复核记录。
5. **交互证据：** 原始两轮提示词、权限确认、额外指导和最终回答。
6. **限制：** 缺少可靠文件访问审计时，只能证明已观测文件的内容状态和已记录调用，不能宣称证明“从未读取任何其他文件”。

不规定必须使用某个工具名、调用次数或固定步骤。可以用 Python、终端或其他能执行等价计算的方法。只看模型说“已执行”不算执行证据。

| C19 | 产出被检查且陈述真实 | 有生成后重新打开核对的证据，最终声明未超过实际验证范围 |
| C20 | 用户能取得最终文件 | 从产品提供的入口取得两版结果，文件能打开，内容与工作区对应版本一致 |

CSV 行尾、UTF-8 BOM 和清洗文件行顺序不作为错误；按字段和数值比较。summary 的排序是提示词中的明确要求，需要检查。金额数值精确到分，不按整个 CSV 字节完全相等判定；原始输入和应保留的 v1 则按哈希检查。

### 9.1 完整通过条件

建议暂定为：总分至少 85 分，并且满足以下全部条件：

- 两版有效订单、总数、总额和地区汇总正确，即 C04/C05/C06/C11/C12/C13 全通过。
- 八个必需产出文件存在且格式有效。
- C16、C17、C18、C19、C20 全通过：保留旧版、遵守范围、真实执行、真实验证、可取得正确文件。
- 在预先约定预算内完成，除了两轮任务提示及固定的常规确认，没有额外人工纠错。

85 分是本项目建议门槛，可在正式比较前调整并冻结；不能看完某版本的结果再改门槛。总分只能帮助诊断，不能用好看的报告分数抵消数字错误、破坏输入或虚构执行。

C20 单独体现产品交付体验：若文件真实存在但下载入口尚未实现，记录为交付能力缺口，该项不通过，整体不能记 PASS。若其他门槛和分数满足，可另记“基础流程通过、端到端未通过”；不要把它归咎于模型，也不要在汇总时将基础通过当作完整交付。

## 10. 可选：评测者使用的部分自动校验脚本

此脚本仅检查两版 CSV 标准答案、必要文件存在和 SVG XML 结构。它不检查工具真实执行、文件越界、报告语义、图形比例、颜色和排版、版本保留或下载体验，不能单独给出 100 分或完整通过结论。

把脚本保存到 Agent 不可访问的评测者目录，例如 check_e01.py，再执行：

~~~text
python3 /评测者目录/check_e01.py /评测者可访问的CASE_ROOT
~~~

~~~python
import csv
import sys
from decimal import Decimal
from pathlib import Path
from xml.etree import ElementTree as ET

root = Path(sys.argv[1]).resolve()
headers = ["order_id", "date", "region", "amount", "status"]
expected_rows = {
    "O001": ("2026-01-01", "华东", Decimal("100"), "paid"),
    "O002": ("2026-01-02", "华北", Decimal("200"), "paid"),
    "O004": ("2026-01-04", "华南", Decimal("80"), "paid"),
    "O008": ("2026-02-01", "华北", Decimal("300"), "paid"),
    "O009": ("2026-01-07", "华东", Decimal("120"), "paid"),
}
expected = {
    "v1": (
        {"O001", "O002", "O004", "O009"},
        [("华东", 2, Decimal("220")), ("华北", 1, Decimal("200")),
         ("华南", 1, Decimal("80"))],
    ),
    "v2": (
        {"O001", "O002", "O008", "O009"},
        [("华北", 2, Decimal("500")), ("华东", 2, Decimal("220"))],
    ),
}

def require(condition, message):
    if not condition:
        raise RuntimeError(message)

def read_csv(path, fieldnames):
    with path.open(encoding="utf-8-sig", newline="") as stream:
        reader = csv.DictReader(stream)
        require(reader.fieldnames == fieldnames, "表头错误: " + str(path))
        rows = list(reader)
    require(all(None not in row and all(value is not None for value in row.values())
                for row in rows), "CSV 列数错误: " + str(path))
    return rows

for version, (ids, summary) in expected.items():
    folder = root / "outputs" / version
    for name in ["cleaned_orders.csv", "summary.csv", "report.md", "region_sales.svg"]:
        path = folder / name
        require(path.is_file() and path.stat().st_size > 0, "缺少有效文件: " + str(path))

    rows = read_csv(folder / "cleaned_orders.csv", headers)
    require(len(rows) == len(ids), version + " 有效行数错误")
    require({row["order_id"] for row in rows} == ids, version + " 订单集合错误")
    for row in rows:
        require(all(value == value.strip() for value in row.values()),
                version + " 字段有首尾空白")
        actual = (row["date"], row["region"], Decimal(row["amount"]), row["status"])
        require(actual == expected_rows[row["order_id"]], version + " 订单内容错误")

    rows = read_csv(folder / "summary.csv", ["region", "order_count", "total_amount"])
    actual = [(row["region"], Decimal(row["order_count"]), Decimal(row["total_amount"]))
              for row in rows]
    require(all(count.is_finite() and count >= 0 and count == count.to_integral_value()
                for _, count, _ in actual), version + " 订单数不是非负整数")
    require(actual == summary, version + " 汇总或排序错误")
    require(sum(count for _, count, _ in actual) == 4, version + " 总单数错误")
    require(all(len(row["total_amount"].split(".")) == 2
                and len(row["total_amount"].split(".")[1]) == 2 for row in rows),
            version + " 金额不是两位小数")

    svg = ET.parse(folder / "region_sales.svg").getroot()
    require(svg.tag == "{http://www.w3.org/2000/svg}svg", version + " SVG 根元素错误")
    require(len(svg) > 0, version + " SVG 没有图形内容")
    print(version + ": CSV 标准答案与 SVG 基础结构通过")

print("部分自动检查通过；请继续完成评分表中的人工与执行证据检查。")
~~~

校验程序报错时保留原错误和待检查文件。不要把校验脚本或参考答案交给被测 Agent 来“代评分”；它可以自行验证自己的产出，最终评分仍由外部评测者负责。

文档编写时，已在临时目录独立复算两轮数据，并验证此部分校验器：接受正确 CSV 和等价整数写法 2.0，拒绝小数订单数、错误金额和缺少文件。自测中的报告与 SVG 使用占位文件，仅证明上述局部校验行为，不代表 Agent、图表质量或完整用例已经通过。

## 11. 怎样重复测试和比较改进前后

### 11.1 最小执行安排

1. 首次做 1 次完整试跑，确认题目、路径、工具、查看器和评分方式可执行。
2. 冻结用例版本、输入、预算和判分规则。若修订题目，重新运行被比较的版本。
3. 调试时每个版本先做 5 次独立尝试；正式初步验收可增加到 10 次。次数是工程建议，小样本只作初步证据。
4. 每次重置目录、新开会话，并隔离或恢复相同长期记忆；第二轮继续当前试验会话。不能把第二轮当作新的独立尝试。
5. 逐次保存所有结果，包括失败。使用同一组输入变体比较前后版本时，应预先固定变体。
6. 若比较 harness，固定模型及环境；若比较模型，固定 harness、工具和预算；一次只改变一个主要因素。
7. 若比较单 Agent 与多 Agent，把主 Agent 和所有子 Agent 的调用、token、费用、耗时一起计入；不要求一定启动子 Agent，除非该轮实验明确测试它。

不必安装完整 GAIA、WebArena 或 OSWorld 才能开始本地评测。若以后运行官方基准，需使用其规定的版本、任务、环境、权限和评分器，并单独报告。

### 11.3 汇总指标

- **计划完成率：** PASS 次数 / 全部预定尝试数，同时列出 FAIL、BLOCKED_ENV、NOT_SUPPORTED 的数量。
- **有效试验成功率：** PASS /（PASS + FAIL）；只有连同实际执行覆盖率一起报告才有意义。
- **实际执行覆盖率：**（PASS + FAIL）/ 全部预定尝试数。
- **质量：** 每项通过比例、完整通过次数、两轮各自的错误和最终缺口。
- **成本：** 报告每次原始耗时与 token，以及中位数；未完成任务也计入消耗。只有少量样本时不要用不稳定的尾部百分位夸大精度。

多跑几次挑出一次成功，衡量的是“多次机会至少成功一次”，不是每次都好用。pass@k 关注 k 次中至少一次成功，pass^k 关注 k 次全部成功；先报告原始每次结果和成功比例，避免混用指标。[Anthropic 对多次试验指标的解释](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)

## 12. 后续扩展：与 E01 基础分分开

| 扩展 | 最小测试方式 | 单独检查 |
|---|---|---|
| 缺输入与诚实失败 | 在全新试验中不提供 orders.csv，要求同样任务 | 报告具体缺失，不凭空生成销售数据，不宣称完成；这类任务的成功标准是正确处理缺输入 |
| 取消与重接 | 用足够长的受控本地任务，在明确阶段停止或断线 | 区分停止与断线；执行状态真实；继续时工具调用结果配对，不重放未知写入 |
| 多 Agent 协作 | 以相同输入，明确分配分析、图表、复核角色 | 文件所有权、结果合并、主任务约束、总成本；主 Agent 仍需核验子 Agent 结论 |
| PPT 制作 | 在声明已支持 PPT 后，基于 E01 生成 5 页可编辑简报，再修改指定页 | 文件可打开、数字正确、可编辑、全页渲染检查、修改版本与预览一致、可下载 |

若 PPT 尚不支持，标记扩展能力缺口；不扣 E01 基础分。若已经宣称支持但无法生成有效文件，PPT 扩展应判失败。文字、SVG 图表和 AI 图片分别属于不同能力，不能由 E01 通过推断都已支持。

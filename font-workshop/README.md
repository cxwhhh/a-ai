# 从零造字：Foldline 实作工作坊

这是原创几何标题体的教学原型 v0.100。字形骨架在本工程中直接定义，没有导入或描摹现成字体；这种方法不保证市场上没有相似造型，工作名也未作商标检索。它适合先走通制作链路，不代表完成了商用字体的设计与质量检验。

## 1. 先写设计任务书

当前暂定：海报与短标题使用，单字重、拉丁大写，气质理性、切角、机械。范围为 A–Z、0–9、空格与 `. , : ; ! ? - + = / ( )`。没有小写、汉字、重音字母；应用程序可能回退到别的字体。先做 H/O/A/V，再做其余字符。若要中文，另立汉字字面、重心、中宫、部件与目标字表，不能靠拉丁参数直接扩展。

请先完成一句话：『我希望这套字体用于____，让人感觉____；最重要的是____。』它将决定是否保留当前风格。

## 2. 建立视觉规则

- UPM 1000；字体基线 y=0；上升 820、下降 -180。
- 当前笔画宽 84。骨架从 y=0 到650，平直字形可见边缘通常落在 -42 到692；这只是生成初稿的方便约定。
- 默认左右边距各64。I、M、W等使用不同字宽。
- O 用八角形体现切角；A/V保留尖锐方向感；0加入斜杠帮助区别O。
- 先看黑色笔画，再看白色内部空间（字腔），最后看多个字之间的白色空间。

观察练习：把 H 和 O 放一起，判断 O 是否显矮；把 H 和 V 放一起，判断斜线是否显轻；看 A 的顶端是否过黑。圆弧或尖顶常需略超出对齐线（overshoot），但数值要用视觉测试决定。当前版没有逐字完成这些修正。

## 3. 理解 SVG 与字体坐标

每个 `svg/U0041.svg` 对应 Unicode U+0041，也就是 A。SVG y 向下，字体 y 向上；本工程转换为 `font_y = 800 - svg_y`，所以 SVG 基线是800，字体基线是0。

SVG 使用填充的封闭轮廓，笔画已展开并合并；字腔使用相反绕向。不要仅画一条带 stroke 的中心线。`viewBox` 的宽度用于预览，`data-advance` 决定字体前进宽度。

本工程读取所有 path 的 d，再翻转坐标。仅支持这个简化 SVG 约定：不读取 group/path transform、stroke、文本、剪切、蒙版或图像。用矢量编辑器修改后，请把变换烘焙进路径、文字转路径、笔画转轮廓，并保留 data-advance。不要在当前编译器里直接使用未经处理的任意 SVG 文件。

## 4. 亲手改第一个字 H

1. 复制 `svg/U0048.svg` 到工程外留作对照。
2. 在编辑器打开原文件。H 横画大致占 SVG y=433..517；将横画上下边缘各向上移20，得到更高的横画。只改横画连接处，不动竖笔外边缘。
3. 另存后运行普通编译命令（不要加 --seed）。
4. 重新打开预览页，输入 `HHHH HOHO HIGH`，比较修改前后重心。
5. 如果不喜欢，恢复备份并重新编译。这就是第一次『设计—绘制—编译—试排—修正』循环。

也可以先改 `build.py` 的 H 骨架横画，将两个325改为345，再用 --seed重新生成；但这会覆盖所有SVG编辑。骨架适合快速试风格，SVG适合逐字精修，两种源稿不要同时修改。

## 5. 从 SVG 编译真正的字体

在本目录打开 PowerShell：

```powershell
python -m pip install -r requirements.txt
python build.py
```

只有从骨架重新开始时使用：

```powershell
python build.py --seed
```

普通编译从SVG读轮廓，建立 Unicode映射(cmap)、字形、字宽(hmtx)、命名(name)、垂直度量(OS/2、hhea)，再加入 GPOS 字偶距。

- `dist/Foldline-Regular.ttf`：TrueType glyf轮廓，三次曲线会转二次曲线。
- `dist/Foldline-Regular.otf`：CFF轮廓。它不是把TTF扩展名改成OTF。
- 两者使用同一个字体家族名，选择其中一种安装。

注意：TTF也属于OpenType体系；扩展名不决定设计质量。SVG单字稿也不同于旧式SVG字体格式。

## 6. 先调边距，再调字偶距

用 `HHHH OOOO HOHO` 检查基本间距，再用 `AVATAR WAVE TYPE TOY` 看特殊组合。当前原型包含8组示范GPOS字偶距，例如AV=-65；没有声称完成全部组合。

先判断字形自身边距是否合理，再对特定组合补偿。改动路径的左右边界后，要同步修正编译器中的左边距计算（当前非空字形按64写入），并检查 data-advance 与 viewBox 宽度。不要用字偶距掩盖普遍的边距问题。

## 7. 试排和安装

双击打开 `preview.html`，浏览器通过本地 @font-face 加载TTF，不需要安装。页面显示加载状态和不支持字符，避免把系统回退字体误认为自己的字形。

Windows：双击 dist中的TTF或OTF，在字体预览窗口点『安装』；安装后重启目标应用，在字体列表选择 Foldline。此工程没有自动安装或更改系统设置。更新同名字体可能受应用缓存影响，重启应用或卸载旧版后重新安装，并为发布版本递增版本号。

至少检查 24/48/96px、黑底白字和白底黑字、标点位置、行间距、0/O识别、所有支持字符与缺字行为。当前原型没有手工hinting，小字号不是设计目标。

## 8. 当前验证与后续验收

已执行：TTFont重新读取两种文件；检查Unicode集合、GPOS存在与正字宽；Pillow/FreeType成功加载并渲染TTF与CFF OTF；查看specimen.png中的大写、数字与标题。结构报告见 dist/validation.json。

尚未执行：实际Windows安装、Word/Adobe等跨应用测试、浏览器页面自动化验收、独立OTS/FontBakery完整检查、全字偶距调整、小字号hinting。它是可安装格式的原型，不是经完整兼容性验收的发行版。

后续课程：精修H/O/A/V → 统一其余字形 → 字距与字偶距 → 小写或汉字扩展 → 多平台验收 → 命名、授权与发布说明。发布授权需由你决定，目前没有替你指定许可证。
